# 内容后台（Studio）部署与使用

后台让你能在浏览器里登录并直接写文章，**不再需要每次改文件、推 GitHub**。

保存文章 → 点「发布到网站」→ 网站更新，全程在浏览器里完成。

---

## 一、它是什么 / 不是什么

**是**：一个轻量的无头 CMS。文章存在 EdgeOne Blob，构建时同步到 `src/content/blog/`，复用站点现有的全部 Markdown 能力（Shoka 语法、数学公式、代码高亮、加密块、测验等原样可用）。

**不是**：所见即所得的富文本编辑器。正文用 Markdown 写，右侧有实时预览。

### 为什么保存后要点「发布」

本站是**纯静态站点**——文章在构建那一刻被烘焙成 HTML 并缓存到边缘。保存文章只是把它写进存储，**必须再构建一次**网站才会显示新内容。

这是静态站架构的固有特性，不是实现缺陷。好处是访问速度极快、成本极低且没有数据库故障面；代价就是内容更新需要一次构建（通常一两分钟）。

## 二、部署步骤

### 1. 生成管理员口令

```bash
node scripts/studio-hash-password.mjs '设一个足够长的密码'
```

会输出两样东西：口令哈希，以及一个随机会话密钥。**明文密码不会被写入任何文件**。

### 2. 在 EdgeOne 控制台配置环境变量

进入 项目 → 设置 → 环境变量，填入上一步生成的值：

| 变量名 | 值 |
| --- | --- |
| `STUDIO_USERNAME` | 你想用的管理员账号 |
| `STUDIO_PASSWORD_HASH` | 上一步输出的 `pbkdf2$...` 整行 |
| `STUDIO_SESSION_SECRET` | 上一步输出的会话密钥 |

### 3. 创建并绑定 Blob 存储

在 控制台 → Blob 存储 中创建一个名为 **`studio-content`** 的存储，然后绑定到本项目。

> 名字必须一致。若想用别的名字，把 `STUDIO_BLOB_NAME` 环境变量一起改掉。

### 4. 创建部署钩子

在 项目 → 设置 → 构建与部署 → 部署触发器 中新建一个钩子（分支选 `main`），拿到 URL 后填入环境变量：

| 变量名 | 值 |
| --- | --- |
| `EDGEONE_DEPLOY_HOOK` | 上一步拿到的钩子 URL |

### 5. 让构建期能拉取文章

后台的文章要在构建时同步回本地，需要两个变量：

| 变量名 | 说明 |
| --- | --- |
| `STUDIO_BLOB_PROJECT_ID` | EdgeOne 项目 ID |
| `STUDIO_BLOB_TOKEN` | EdgeOne API Token（只读权限即可） |

> **不配也能用**：这两个变量缺失时同步脚本会静默跳过，已提交到仓库的文章照常构建。你只是暂时看不到后台里写的文章。

### 6.（可选）登录限流

再绑定一个 KV 命名空间（变量名 `STUDIO_KV`），即可启用「同一 IP 15 分钟内失败 8 次则暂时封锁」的保护。不配也能正常登录，只是少了这层防护。

## 三、日常使用

| 操作 | 路径 |
| --- | --- |
| 登录 | `你的域名/studio` |
| 文章列表 | `你的域名/studio/posts` |
| 新建 | 列表页右上角「写新文章」 |
| 编辑 | 列表里点「编辑」，或直接访问 `/studio/posts/<slug>` |

**发布流程**：写完后点「保存」，再点右上角「发布到网站」。等构建完成（一两分钟），刷新网站即可看到。

在编辑器里按 `Ctrl/Cmd + S` 可以直接保存。

---

## 四、几个设计决定

**URL 短名（slug）独立于标题。** 改标题不会改变文章链接，已发布出去的链接不会失效。新建时会根据标题自动生成，可以手动改。

**草稿不会上线。** 勾选「存为草稿」后，文章只存在于后台，构建时会被跳过，网站上访问不到。适合写一半的东西。

**图片走后台代理。** 上传的图片按内容哈希命名，保存在 Blob 里，通过 `/api/studio/media/<文件名>` 访问。相同图片重复上传不会产生副本。

## 五、安全说明

- 口令只存 **PBKDF2-SHA256 哈希**（10 万次迭代 + 随机 salt），仓库里没有明文
- 会话是 **HMAC 签名的 httpOnly Cookie**，JavaScript 读不到，有效期 7 天
- 所有写操作都在服务端校验会话，前端绕过无从下手
- 登录失败有**恒定时间比较**，无法从响应耗时区分「账号错」还是「密码错」
- `/studio` 已加入 `robots.txt` 的 Disallow，页面带 `noindex`，不会被搜索引擎收录
- 后台不加入任何导航入口，只有知道地址的人才能找到登录页
- **未配置 `STUDIO_USERNAME` / `STUDIO_PASSWORD_HASH` 时，所有接口一律返回 404** —— 即使忘记关掉功能，也不会暴露一个无人管理的登录入口

### 想关掉后台

把 `config/site.yaml` 里的 `admin.enabled` 改为 `false`，或直接在 EdgeOne 控制台清空 `STUDIO_PASSWORD_HASH`（后者会立即让接口失效，无需重新部署）。

## 六、故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 登录页 404 | `STUDIO_USERNAME` / `STUDIO_PASSWORD_HASH` 未配置，或项目未重新部署 |
| 登录提示「账号或密码错误」 | 哈希可能被换行符污染；重新跑一次生成脚本，注意复制完整一行 |
| 提示「内容存储未绑定」 | Blob store 未创建，或名字不是 `studio-content` |
| 提示「尚未配置部署钩子」 | 缺 `EDGEONE_DEPLOY_HOOK`，保存不受影响，可手动在控制台点构建 |
| 保存成功但网站没变化 | 还没触发构建。点「发布到网站」，或检查构建是否失败 |
| 构建时文章没同步过来 | 检查 `STUDIO_BLOB_PROJECT_ID` / `STUDIO_BLOB_TOKEN`，看构建日志里 `[studio:pull]` 那几行 |
| 登录后立刻被踢回登录页 | Cookie 需要 HTTPS；本地 `http://localhost` 调试时 Secure Cookie 不会保存，属预期行为 |

## 七、自测

改完 API 后可以跑一遍内置的端到端测试，它会在内存里模拟 EdgeOne 的 Blob 存储，真实执行登录、鉴权、增删改查、图片上传与发布全过程：

```bash
npm run studio:test
```

预期输出结尾为 `=== 结果：39 通过 / 0 失败 ===`。

涉及的文件：

| 文件 | 作用 |
| --- | --- |
| `scripts/studio-test-api.mjs` | 39 个测试用例（登录 / 会话 / 鉴权 / CRUD / 图片 / 发布 / 路由） |
| `scripts/studio-test-preload.mjs` | 注册 ESM loader，把 `@edgeone/pages-blob` 重定向到内存替身 |
| `scripts/studio-test-loader.mjs` | 由 preload 自动生成，实际的重定向逻辑 |
| `scripts/studio-test-mock-blob.mjs` | 由 preload 自动生成，内存版 Blob 存储 |

> 后两个文件是运行时自动生成的，已在 `.gitignore` 中忽略，不用手动维护。
