这类清单最容易写成广告：每个工具都"强大、优雅、提升效率 10 倍"。我尽量换个写法——只写我拿它干什么、为什么半年后它还在我任务栏上。

平台是 Windows 11，所以有些工具偏 Windows。一共八个。

## VS Code：写业务代码的地方

我试过换过一次，两周后回来了。留它的原因很具体：TypeScript 的项目级重构（改名符号、提取函数）在我试过的编辑器里只有它做到"改 40 个文件不出错"；Remote SSH 连服务器改 nginx 配置时，插件和本地完全一致。

我用一个极简配置：不装主题，不装图标包，装的插件只有七个（Volar、Biome、GitLens、Error Lens、Tailwind IntelliSense、Remote SSH、Markdown 预览）。前年我装过 30 多个，启动 8 秒；现在冷启动 1.6 秒。

一个用得最多的快捷键是 `Ctrl+Shift+P` → `Reopen with Encoding`，处理中文乱码的旧文件比什么都快。

## Zed：读代码的地方

打开一个陌生仓库，我用 Zed。它的冷启动在 0.4 秒左右，`Ctrl+P` 全文模糊搜索是即时出结果的，看别人项目时这种"手指比脑子快"的体感很重要。

我不拿它写大项目，原因是 TypeScript 的语言服务在超大 monorepo 里偶尔会断连，需要重启。但读代码、写脚本、临时打开一个 markdown，它比 VS Code 顺手。

顺带说：它的 AI 补全我用了一周就关了。不是不好用，是我发现自己开始不看不补全之后的那几行。

## Windows Terminal + PowerShell 7：所有杂活

终端我只做四件事：跑构建、git、ssh、批量改文件。Windows Terminal 的标签页和分屏够用，PowerShell 7 的 `&&` 和 `||` 支持让我终于不用写 `; if ($?) {}`。

配了 `oh-my-posh` 但只留了 git 分支和当前路径两段提示符——之前那个带天气、时间、K8s 集群、电池状态的配置，每次打开终端要多等 300ms，而我从来没看那些信息。

## Obsidian：300 篇笔记，全在本地

我的笔记库有 300 多篇 markdown，从 2022 年一直搬到现在，`.md` 文件从来没有被任何应用锁死过。这点对我很重要：我换过四次笔记软件，每次都因为导出格式崩掉损失过东西。

实际用法很朴素：

- 每天一篇日记，标题是日期，跑 `Daily notes` 自动生成；
- 所有技术笔记用 `[[ ]]` 双链到一个主题页，比如 `[[Astro]]`；
- 写博客前先在这里写草稿，写完连 frontmatter 一起复制到仓库。

插件只留了三个：Dataview（做索引页）、Templater（模板）、Advanced Tables。装了 Dataview 之后我做了一个"所有没被任何笔记链接到的孤儿笔记"列表，清掉了 80 多篇写了没用的碎片。

## Snipaste：截图和贴图

`F1` 截图，`F3` 把截图贴回屏幕上。第二个功能是它不可替代的原因。

写界面的时候我会把设计稿截一块贴在屏幕角落，一边调 CSS 一边用眼睛比间距。这个动作以前要来回切窗口，现在屏幕上是浮着的，可以钉住、缩放、半透明。

它还支持取色：截完图按 `C` 复制色值，配色对不齐的时候比开开发者工具快。

## Ditto：剪贴板历史

Windows 自带的 `Win+V` 我用了一年，最后换回 Ditto，原因是两个：`Win+V` 不能固定常用片段，也不能搜索历史。Ditto 里我固定了六条：邮箱、许可证 key、常用的 `ssh` 命令、一段 git 提交模板、两个常发的地址。

`Ctrl+`反引号呼出，输入两个字母就能筛。剪贴板历史里我最常找的是"十分钟前复制的那段报错"，这个场景 `Win+V` 的 25 条上限不够用。

## Everything：找文件

按文件名搜索，索引 NTFS 的 USN 日志，整块盘搜完是毫秒级。我主要用它两件事：

- 在 `node_modules` 里找某个包的类型声明文件，确认某个 API 到底存不存在；
- 用 `!` 排除路径，比如 `*.md !node_modules !.git`，比在 VS Code 里搜快得多。

它不能搜文件内容（那是另一个工具的事），但"我知道文件名，就忘了在哪"这个场景它没有对手。

## Zen Browser：把工作和查资料分开

基于 Firefox 的一个分支，主打垂直标签页和工作区（Workspace）。我是被"两个工作区互不干扰"这一点留下的：一个工作区是项目相关的 12 个标签（文档、CI、后台、issue），另一个是随手查的 20 多个。切换的时候不会看到另一边的标签，心理上清爽很多。

垂直标签页在宽屏上比横向省空间，标题能完整显示，不会变成一堆 favicon。缺点是它对某些只测 Chromium 的内部系统兼容不好，我留了一个 Edge 专门开那些。

## 今年卸载掉的三个

- **Notion**：我用它管理过一段时间的项目，最后放弃是因为离线几乎不可用，地铁上打开一个页面转圈 20 秒。内容导出成 markdown 之后表格结构丢了一半。
- **Postman**：换成 `curl` 加 `.http` 文件。接口调试的记录现在跟代码放在同一个仓库里，比存在云端账号里更可靠。
- **一个"第二大脑"类插件**：它自动给我生成"关联笔记"，生成的关联里 90% 是废话。机器猜的关系，不如我自己写一条双链。

## 今年最大的变化：不再追新工具

去年我大概试了 40 多个新工具，今年不到 10 个。不是变懒了，是想明白一件事：**换工具的成本不在安装，在肌肉记忆**。一个新工具要花两周才能进到"不看菜单就能操作"的程度，而这两周里我的产出是下降的。

所以现在的标准很粗暴：现有的工具能不能通过一个快捷键或一个脚本解决？能，就不换。今年唯一破例的是 Zed，因为它解决的是"打开要等"这个我每天遇到 20 次的问题。

清单不是目的。能说出来"我拿它干什么"，才算真的在用。
